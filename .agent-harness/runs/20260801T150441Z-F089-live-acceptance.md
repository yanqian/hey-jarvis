# F089 target-Mac live acceptance

Date: 2026-08-01
Feature: F089 - Add BYOK Keychain setup and first-run recovery
Platform: Apple Silicon Mac, Tauri development build, repository Python 3.12 runtime

## Authorization and privacy boundary

The user interactively operated the local Hey Jarvis development app and
authorized the microphone/OpenAI Realtime trial. No API-key value, raw audio,
or transcript is recorded in this evidence. The user confirmed that the native
Settings UI could add both the required OpenAI key and optional Finnhub key,
and that the UI only reported configured status rather than displaying either
value.

## Settings recovery findings

The first trial exposed that the loopback voice page could not return reliably
to the native Settings frontend. Debugging established that Tauri CLI injects
a dynamic built-in development-server URL when `frontendDist` is used without
`devUrl`; navigating from the loopback page to a hard-coded
`tauri://localhost` URL therefore entered an empty embedded-asset table and
returned `asset not found: index.html`.

The corrected flow preserves the actual native frontend history entry and
returns through browser history, while the tray resolves its destination from
Tauri runtime configuration. A `#settings-return` marker keeps the UI in
non-listening Settings mode across BFCache restoration and a subsequent dev
server document load. Native lifecycle diagnostics proved the former race as
`enter_settings -> stop(open_settings) -> onboarding_status`, followed by a
second `onboarding_status -> sidecar_status` only after the marker had been
cleared. Keeping the marker for the Settings lifetime removed that overwrite.

The user then confirmed that:

- the runtime page has a visible Settings action;
- Settings returns without a 404;
- the sidecar stops while Settings is open;
- the Settings page remains visible after waiting;
- the stopped-listening message remains available across the development
  document reload; and
- `Check microphone & start` releases its temporary check stream, starts the
  runtime, and reaches the explicit `Runtime ready`/Arm page.

The development build initially launched the system Python 3.14 interpreter
and failed before readiness. Repository inspection showed that `.venv` is
Python 3.12.13, within the documented supported range. Debug builds now prefer
that repository interpreter when present while retaining the explicit
`HEY_JARVIS_SIDECAR_PYTHON` override; release packaging remains F090 scope.

## Live voice result

After Arm, WKWebView reported `echoCancellation=true` and a 48 kHz capture
rate; fields WebKit did not expose remained explicitly `not reported`. The
ordered bounded page events included `armed`, `remote_audio_track`,
`transport_connected`, `session.created`, and `input_ready`.

The user confirmed all of the following on the current product path:

- a normal spoken question received the correct answer;
- a follow-up worked without another wake phrase;
- natural interruption stopped the old answer and answered the new question;
- the exact spoken end phrase “再见” closed the session; and
- the page returned to `Armed · Python wake microphone restored`.

This accepts the configured-key Settings path, Settings recovery, runtime
startup, Arm, multi-turn conversation, barge-in, end phrase, and wake recovery
for this target-Mac run. The separate real TCC microphone-denial/re-enable
trial is recorded below.

## Standalone app and real TCC recovery

A standalone unsigned debug app was built with the product bundle identifier
`com.heyjarvis.desktop` so macOS attributed microphone permission to Hey
Jarvis rather than to the terminal-hosted development process. This trial also
found a loopback bootstrap compatibility defect: the one-time capability URL
redirected from the `tauri://localhost` top-level origin, but WebKit did not
send a `SameSite=Strict` cookie after that cross-site navigation and the host
returned `{"error":"forbidden"}`. The cookie is now `HttpOnly; SameSite=Lax`,
which permits this top-level safe navigation while continuing to exclude
cross-site subresource and unsafe-method requests.

After that correction, the user completed the following real macOS TCC trial:

- denied the standalone Hey Jarvis microphone request;
- observed that the app remained in non-listening Settings mode with an exact
  permission-denied explanation and an Open System Settings recovery action;
- enabled the `Hey Jarvis` entry under Privacy & Security -> Microphone;
- reran `Check microphone & start` and reached the explicit `Runtime ready`
  page; and
- clicked `Arm hands-free audio` and confirmed the app entered the armed
  listening state.

This accepts the required microphone denial-and-recovery path on the target
Mac. The earlier interactive setup also exercised first-run disclosure, adding
the required OpenAI credential and optional Finnhub credential, configured-only
status rendering, and readiness startup without recording a credential value.
