## Scope

- Added a structured `RealtimeCallError` that extracts at most 4096 bytes from
  rejected OpenAI Realtime calls and keeps only bounded provider `type` and
  `code` strings plus the upstream HTTP status.
- The loopback `/session` endpoint retains its compatibility 409 while returning
  a stable safe object with the distinct upstream status.
- Added an executable browser sanitizer that distinguishes local and upstream
  statuses, forwards only allowlisted fields, and is included explicitly in the
  PyInstaller sidecar asset list.
- Updated coordinator and assisted-diagnosis sanitization so the existing local
  report preserves the safe fields and drops legacy response-header metadata.

## Regression And Privacy Evidence

- Deterministic upstream 400, 401, 403, 404, 429, 500, and 503 failures retain
  only status, provider type, and provider code.
- Provider message, parameter, response body, headers, API key-like strings,
  malformed JSON, unsafe characters, and over-100-character values are absent
  from the returned and persisted payloads.
- Bodies over 4096 bytes and network failures degrade to generic safe evidence;
  no retry or paid preflight was introduced.
- The browser now reports `localHttpStatus: 409` separately from the real
  `upstreamHttpStatus`, preventing the earlier false attribution.
- No live microphone, speaker, credential mutation, paid Realtime session, or
  live provider call was used during automated verification.
